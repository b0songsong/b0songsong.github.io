나만의 GitHub Pages 블로그를 시작하며

개발과 보안 공부를 연결하는 작은 기록 공간의 구조와 운영 방식을 정리한다.

보송송2026.10.27약 2분 읽기예시 노트
GitHub PagesMarkdown기록
블로그 구성을 위한 예시 노트이다. 실제 문제 풀이, 취약점 제보, 수상 또는 자격 취득 실적을 의미하지 않는다.

GitHub Pages는 무엇인가

GitHub Pages는 저장소에 있는 HTML, CSS, JavaScript 등의 정적 파일을 웹사이트로 제공하는 서비스이다. 개인 사이트의 저장소를 사용자명.github.io로 만들면 기본 주소가 https://사용자명.github.io/ 형태가 된다. 일반 프로젝트 저장소는 기본 주소 뒤에 저장소 이름이 붙는다. 자세한 구조는 GitHub Pages 공식 설명에 정리되어 있다.

이 블로그에서는 Markdown으로 글을 작성하고, 그 내용을 HTML로 변환해 공개한다. GitHub Actions를 사용하면 저장소의 변경 사항에 맞춰 빌드와 배포를 실행할 수 있다. 공식 워크플로 안내를 참고할 수 있다.

여섯 개의 서랍으로 기록한다

공부한 내용을 다시 찾기 쉽도록 기록의 목적에 따라 카테고리를 나눈다.

카테고리 담을 내용
개발 언어, 자료구조, 도구 구현과 디버깅
CTF/Wargame 문제 분석 과정, 풀이와 회고

논문/컨퍼런스 논문 읽기, 발표 자료와 세미나 정리
공모전/자격증 준비 계획, 학습 과정과 활동 회고

주제가 겹치는 경우에는 글의 주된 목적에 맞는 카테고리 하나를 선택하고, 세부 주제는 태그로 덧붙인다. 예를 들어 C++로 만든 분석 도구의 구현 설명은 개발에, 그 도구를 사용한 문제 풀이는 CTF/Wargame에 둘 수 있다.

이해하고, 재현하고, 기록한다

이 공간의 소개 문구는 “이해하고, 재현하고, 기록한다”이다. 용어를 이해하는 단계에서 시작해 작은 예제로 확인하고, 다른 사람이 따라갈 수 있는 문장으로 정리하는 흐름을 담았다.

글마다 학습 목표, 확인한 내용, 남은 질문을 적는 습관을 들이는 것이 운영 계획이다. 오류를 발견하면 수정 이유와 확인한 자료를 덧붙인다.

첫 글을 자신의 기록으로 바꾸기

블로그 이름과 자기소개를 먼저 다듬고, 가장 최근에 공부한 주제로 글 한 편을 작성한다. 기존 예시 글은 본인의 기록으로 고치거나 삭제하면 된다. 카테고리를 모두 채우는 속도보다, 한 편의 글을 읽고 당시의 생각을 다시 이해할 수 있는지를 기준으로 삼는다.
