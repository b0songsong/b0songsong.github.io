C/C++ 메모리를 읽는 첫 번째 기준

주소, 값, 객체의 수명을 구분하며 메모리 코드를 읽는 연습이다.

보송송2026.10.27약 2분 읽기예시 노트
C/C++메모리포인터
블로그 구성을 위한 예시 노트이다. 실제 문제 풀이, 취약점 제보, 수상 또는 자격 취득 실적을 의미하지 않는다.

주소와 값을 나누어 읽는다

포인터 코드를 볼 때는 변수가 저장한 값과 그 값이 가리키는 객체를 구분하는 것부터 시작한다. C++ 포인터는 객체의 주소를 저장하며, 역참조를 통해 해당 객체에 접근할 수 있다. 기본 개념은 Microsoft의 포인터 설명에서 확인할 수 있다.

int value = 10;
int* ptr = &value;

*ptr = 20;

이 예제에서 value는 정수 객체이고, ptr은 value의 주소를 담은 포인터이다. 마지막 문장은 포인터 자체의 값을 바꾸는 것이 아니라, 그 포인터가 가리키는 정수 객체의 값을 20으로 바꾸는 것이다.

표현 이 예제에서의 의미
value 정수 객체의 값
&value 정수 객체의 주소
ptr 포인터에 저장된 주소
*ptr 그 주소가 가리키는 정수 객체

수명을 함께 확인한다

주소가 들어 있다는 사실만으로 안전하게 접근할 수 있는 것은 아니다. 그 주소의 객체가 아직 존재하는지 확인해야 한다. 직접 동적 할당을 사용하는 코드라면 할당과 해제의 짝도 확인한다. new로 생성한 객체는 delete, new[]로 생성한 배열은 delete[]와 대응한다.

코드 리뷰에서는 세 가지 질문을 먼저 적어 두면 좋다.

  1. 이 객체를 누가 만들었는가?
  2. 어느 시점까지 접근할 수 있는가?
  3. 해제 이후에도 해당 주소를 사용하는 코드가 있는가?

현대 C++의 자원 관리 방식은 스마트 포인터 문서를 함께 읽으며 확장할 수 있다.

디버깅 노트에는 예상도 남긴다

디버거의 출력만 복사하면 나중에 왜 해당 값을 확인했는지 잊기 쉽다. 관찰하기 전에 예상 결과를 적고, 실행 후 실제 결과와 비교한다. 위 예제라면 마지막 문장을 실행한 뒤 value가 20이 되는지 확인하는 식이다.

이때 특정 주소를 외우기보다 어떤 객체와 포인터가 연결되어 있는지를 기록한다. 다음 글에서는 작은 배열을 예제로 원소 접근과 배열의 길이를 함께 정리할 계획을 세울 수 있다.
