정보보호 분야에 관심을 가진 뒤 부족한 전공 지식과 보안 역량을 강화하기 위해 꾸준히 학습해 왔다. 처음에는 무엇부터 공부해야 할지 막막했지만, 컴퓨터공학 기초부터 워게임과 CTF, 펌웨어 분석, 자동차 퍼징까지 조금씩 활동 범위를 넓혀 왔다.

이번 글에서는 완료한 활동과 현재 진행 중인 시도를 구분해 돌아보고, 그 과정에서 발견한 부족한 점과 앞으로의 계획을 정리하고자 한다.

## 전공 기초 다지기

먼저 보안 학습의 기반이 되는 컴퓨터공학 지식을 공부했다. 자료구조를 학습하며 연결 리스트, 스택, 트리 등의 구조와 동작 방식을 이해했고, 소켓 프로그래밍을 통해 TCP/IP 통신과 클라이언트·서버 구조를 익혔다. 학습한 내용을 적용하기 위해 소켓 기반 채팅 프로그램도 구현했다.

이 과정에서 개념을 읽는 것만으로는 충분하지 않으며, 직접 코드를 작성하고 오류를 해결해야 제대로 이해할 수 있다는 점을 배웠다. 이는 이후 보안 문제에서 데이터가 프로그램과 네트워크를 통해 전달되는 과정을 분석하는 기초가 되었다.

## 워게임과 CTF

드림핵에서 시스템 해킹 학습을 시작해 스택 버퍼 오버플로우와 Use-After-Free 등의 취약점 발생 원리를 공부했다. 워게임을 풀면서 리눅스 시스템의 보호 기법과 우회 방법도 익혔다.

이후 CTF에 참가해 학습한 내용을 실제 문제에 적용했다. 특히 자동차 CTF에서는 CAN, ISO-TP, UDS 통신을 분석하고 진단 세션 전환, DID 조회와 SecurityAccess 등의 과정을 경험했다. 문제를 푼 뒤에는 풀이 과정을 정리하며 이해하지 못한 개념을 다시 확인했다.

## CTF에서 경험한 AI 활용

최근 CTF에서는 대부분의 참가자가 AI를 활용하고 있었으며, 모든 코드와 데이터를 직접 분석하는 것보다 AI를 이용하는 편이 훨씬 빠른 경우가 많았다. 하지만 비슷한 AI와 분석 도구를 사용해도 참가자별 성과는 달랐다. 이를 통해 도구 자체보다 문제를 나누는 방식, 질문의 정확성, 결과를 검증하는 능력이 중요하다는 것을 느꼈다.

이러한 경험을 바탕으로 자동차 CTF를 준비하며 AI 에이전트 기반 문제 풀이 자동화 시스템을 구축했다. 리버싱, 포너블, 암호학과 CAN 분석 환경을 구성하고, 문제 분석과 결과 검토를 에이전트가 스스로 하도록 만들었다. 완성한 시스템은 실제 대회에서도 사용했다.

그러나 기대한 만큼의 성과를 얻지는 못했다. 자동차 통신과 ECU에 대한 지식이 부족해 AI의 풀이 직접 실시간으로 검수할 때 피드백하기 어려웠고, 문제를 해결한 뒤에도 구체적인 풀이 과정을 이해하지 못해 Write-up 작성에 어려움을 겪었다.

이를 통해 AI가 만든 풀이를 자신의 언어로 설명하지 못한다면 문제를 온전히 이해했다고 보기 어렵다는 점을 깨달았다. AI를 잘 활용하려면 도구 사용 능력뿐 아니라 결과를 판단할 수 있는 기초 지식과 도메인 지식이 필요했다.

## 펌웨어 분석

현재 IP 카메라 펌웨어를 대상으로 파일 시스템과 내부 바이너리를 분석하고 있다. 분석 대상이 IP 카메라인 만큼 주요 취약점 후보는 웹 서비스와 관련되어 있었으며, 웹 요청으로 전달된 입력이 내부 프로그램에서 처리되는 과정을 중심으로 살펴보았다.

### 완료한 것

펌웨어의 파일 시스템을 추출하고 부팅 스크립트와 네트워크 서비스의 실행 구조를 분석했다. 이후 발견한 취약점 후보 가운데 하나를 선정해 부분 에뮬레이션 환경에서 동적으로 검증했다.

AI를 활용해 실제 기기 없이 취약 동작을 재현할 수 있는 수준의 PoC를 작성하고, 부분 에뮬레이션 환경에서 예상한 결과가 발생하는 것도 확인했다.

### 현재까지 확인한 것

정적 분석에서 발견한 의심스러운 코드가 부분 에뮬레이션 환경에서도 예상한 동작으로 이어지는 것을 확인했다. 이를 통해 코드를 보고 취약 가능성을 추측하는 단계에서 더 나아가, 실행 결과를 바탕으로 취약점 후보를 검토할 수 있었다.

### 아직 확인하지 못한 것

PoC 작성과 분석 과정에서 AI의 도움을 많이 받았기 때문에 코드의 모든 동작과 취약점 발생 과정을 스스로 설명하거나 다시 구현할 수 있는 수준에는 도달하지 못했다. 실제 기기에서도 같은 현상이 발생하는지는 아직 검증하지 않았다.

또한 웹 요청 처리, 인증과 세션, 웹 서버 구조에 대한 지식이 부족해 입력이 취약 동작으로 이어지는 전체 과정을 깊이 있게 이해하는 데 한계가 있었다.

## 자동차 퍼징

자동차 퍼징에서는 DBC를 바탕으로 CAN 메시지와 시그널의 의미를 분석하고 있다. 현재는 DBC에 정의된 메시지별 시그널 값과 전송 주기를 변형해 뮤테이션 입력을 생성하고 있다.

### 완료한 것

여러 CAN 버스에서 발생하는 메시지를 동시에 수집하고 하나의 로그로 남길 수 있는 환경을 구축했다. 이를 통해 특정 입력을 전송했을 때 각 버스에서 어떤 메시지 변화가 발생했는지 함께 비교할 수 있게 되었다.

### 현재까지 확인한 것

퍼징 과정에서 우연히 이상 반응으로 보이는 현상을 관찰한 적이 있다. 그러나 동일한 입력을 다시 전송했을 때 해당 반응이 반복적으로 발생하지 않아, 퍼징 입력과 차량 반응 사이의 인과관계는 아직 확인하지 못했다.

### 아직 확인하지 못한 것

현재 가장 큰 과제는 수집한 로그에서 무엇을 이상 반응으로 판단할 것인지 구체적인 기준을 정하는 것이다.

실험에 사용하는 차량은 평소에도 창문이 저절로 내려가거나 시동이 원활하게 걸리지 않는 등 상태가 좋지 않다. 따라서 실험 중 나타난 현상이 퍼징 입력 때문인지, 기존 차량 상태에서 발생한 문제인지 구분하기 어렵다.

이 때문에 평소와 다른 현상을 발견하는 것만으로는 이상 반응이라고 판단하기 어렵다. 정상 상태의 범위와 기존 고장을 먼저 정의하고, 해당 기준을 벗어난 변화가 동일한 입력에서 반복적으로 발생하는지 확인해야 한다.

## 부족했던 점과 앞으로의 계획

### 기초 지식과 도메인 지식

자료구조와 네트워크, 시스템 해킹을 공부했지만 운영체제, 메모리 구조, C/C++와 어셈블리 지식을 실제 분석 과정에 연결하는 능력은 아직 부족하다. 자동차 분야에서도 CAN, ISO-TP, UDS와 ECU 상태에 대한 이해를 보완해야 한다.

앞으로는 기초 개념을 다시 공부하면서 워게임과 CTF에서 만난 취약점에 연결해 정리할 예정이다. 자동차 보안은 프로토콜의 형식만 외우는 것이 아니라 각 메시지와 진단 기능이 ECU 상태에 어떤 영향을 주는지를 중심으로 학습하고자 한다.

### AI 결과에 대한 독립적인 이해

AI를 활용해 CTF 문제를 풀고 펌웨어 취약점 PoC를 작성했지만, 생성된 결과의 모든 과정을 직접 설명하거나 다시 구현하지는 못했다.

현재 작성된 PoC를 기능별로 나누어 분석하고, 핵심 동작은 AI의 도움 없이 다시 구현해 볼 계획이다. AI 에이전트 시스템에도 사용한 명령과 분석 근거, 생성 결과와 검토 내용을 자동으로 저장하는 기능을 추가해 CTF 종료 후 복습과 Write-up 작성에 활용하고자 한다.

### 웹 보안 지식

IP 카메라 펌웨어에서 발견한 주요 취약점 후보가 웹 서비스와 관련되어 있었지만, HTTP 요청 처리와 인증, 세션, 웹 서버 구조에 대한 지식이 부족했다.

이를 보완하기 위해 웹 서버의 요청 처리 과정과 주요 웹 취약점을 학습하고, 현재 PoC의 입력이 펌웨어 내부에서 어떤 함수를 거쳐 처리되는지 다시 추적할 예정이다. 현재 분석과 관련된 학습을 충분히 마친 뒤에는 실제 기기와 함께 새로운 펌웨어 분석을 진행하고자 한다.

### 자동차 퍼징의 이상 반응 판단과 재현

여러 버스의 메시지를 수집하는 환경은 구축했지만, 정상 동작과 이상 반응을 구분하는 기준은 아직 확립하지 못했다. 차량의 기존 문제까지 존재하기 때문에 퍼징 입력의 영향만 분리해 판단할 수 있는 실험 설계가 필요하다.

먼저 퍼징 입력을 전송하지 않은 상태에서 차량 반응과 여러 버스의 메시지를 반복적으로 수집해 정상 기준선을 만들 계획이다. 기존 차량에서 발생하는 문제도 별도로 기록하고, 실험 시작 전 차량과 ECU의 상태를 가능한 한 동일하게 맞추고자 한다.

이후 입력값과 전송 주기, 메시지 순서, 차량 반응과 오류 로그를 하나의 기록으로 관리할 예정이다. 동일한 입력을 자동으로 반복 전송하고, 정상 기준선을 벗어난 변화가 반복해서 나타나는지 확인할 수 있는 재현 절차도 구축하고자 한다.

## 마무리

지금까지의 활동은 성과를 쌓는 동시에 앞으로 해결해야 할 문제를 발견하는 과정이었다. 앞으로는 AI와 자동화 도구를 활용하되 그 결과를 직접 이해하고 검증하며, 반복 가능한 실험과 근거를 통해 분석 결과를 설명할 수 있는 보안 전문가로 성장하고 싶다.
