기업과 기관의 네트워크에는 정상적인 업무 트래픽뿐 아니라 취약점 탐색, 계정 탈취 시도, 악성코드 통신과 같은 위협 트래픽도 함께 오간다.

전통적인 방화벽은 주로 IP 주소, 포트, 프로토콜과 같은 통신 정보를 기준으로 접근을 통제한다. 하지만 정상적으로 허용된 웹 통신 안에 SQL Injection 공격 코드가 포함되는 경우처럼, 허용된 연결 내부에서 발생하는 공격까지 항상 식별할 수 있는 것은 아니다.

이처럼 네트워크와 시스템에서 발생하는 공격을 찾아내고 대응하기 위해 사용하는 대표적인 보안 시스템이 IDS와 IPS다.

> IDS는 공격을 탐지하고 기록하며, IPS는 탐지한 공격을 직접 차단한다.

## 1. IDS와 IPS란?

### IDS: 침입 탐지 시스템

IDS(Intrusion Detection System)는 네트워크 트래픽이나 시스템 활동을 감시해 공격으로 의심되는 행동을 탐지하는 시스템이다.

공격을 발견하면 발생 시간, 출발지와 목적지 IP 주소, 공격 유형, 위험도 등의 정보를 기록하고 관리자에게 알린다. 기본적인 목적은 탐지와 경고이므로 원본 통신을 직접 차단하지 않는 경우가 많다.

### IPS: 침입 방지 시스템

IPS(Intrusion Prevention System)는 공격을 탐지하는 데서 끝나지 않고, 해당 트래픽이나 행위가 실제 피해로 이어지지 않도록 직접 차단하는 시스템이다.

네트워크 기반 IPS는 공격 패킷을 폐기하거나 연결을 종료할 수 있다. 호스트 기반 IPS는 악성 프로그램 실행이나 중요 파일 변경처럼 시스템 내부에서 발생하는 행위를 제한할 수 있다.

### IDS와 IPS 핵심 비교

| 구분 | IDS | IPS |
| --- | --- | --- |
| 정식 명칭 | Intrusion Detection System | Intrusion Prevention System |
| 주요 역할 | 공격 탐지, 기록, 알림 | 공격 탐지 및 실시간 차단 |
| 일반적인 배치 | NIDS는 원본 통신 경로 밖에서 미러링된 트래픽 분석 | NIPS는 원본 통신 경로상에 인라인으로 배치 |
| 공격 발견 시 | 경고와 로그 생성 | 패킷 폐기, 연결 종료 등 |
| 서비스 영향 | 비교적 적음 | 오탐이나 장애 발생 시 서비스에 영향을 줄 수 있음 |
| 장점 | 폭넓은 감시와 사고 분석에 유리 | 공격이 서버에 도달하기 전에 차단 가능 |
| 주의점 | 탐지 후 별도의 대응이 필요할 수 있음 | 정책과 성능을 신중하게 관리해야 함 |

> 위 배치 방식은 네트워크 기반인 NIDS와 NIPS를 기준으로 한다. HIDS와 HIPS는 보호 대상 서버나 PC에 설치된다.

쉽게 비유하면 IDS는 CCTV와 비슷하다. 수상한 행동을 확인하고 기록하지만 직접 출입을 막지는 않는다. IPS는 출입구의 보안요원처럼 수상한 행동을 확인한 뒤 실제로 출입을 제한한다.

다만 실제 환경에서 IDS와 IPS가 반드시 별도의 장비로 구분되는 것은 아니다. 하나의 보안 장비가 동일한 탐지 엔진을 이용해 경고만 발생시키는 탐지 모드와 공격을 차단하는 방지 모드를 모두 제공하기도 한다.

최근에는 차세대 방화벽인 NGFW에 애플리케이션 분석과 IPS 기능이 함께 포함되는 경우도 많다. 따라서 실제 제품을 구분할 때는 장비의 이름보다 배치 방식과 활성화된 대응 정책을 확인하는 것이 중요하다.

## 2. IDS와 IPS의 동작 원리

여기서는 네트워크 기반 제품인 NIDS와 NIPS를 중심으로 동작 방식을 살펴본다. 호스트 기반 제품은 네트워크 경로가 아니라 서버나 PC 내부에서 로그, 파일, 프로세스 등의 활동을 분석한다.

NIDS와 NIPS는 모두 트래픽을 수집한 뒤 분석 엔진을 이용해 공격 여부를 판단한다. 차이는 원본 통신을 복사해 관찰하는지, 통신 경로에 직접 배치되어 패킷 처리에 개입하는지에 있다.

### NIDS의 동작 방식

NIDS는 일반적으로 스위치의 미러링 포트나 네트워크 TAP을 통해 복사된 트래픽을 전달받는다.

```text
네트워크 트래픽 수집
        ↓
패킷 정규화 및 세션 재구성
        ↓
탐지 규칙과 이상 행위 분석
        ↓
보안 이벤트 생성
        ↓
관리자 알림 및 로그 저장
```

NIDS는 원본 통신이 아닌 복사된 트래픽을 분석한다. 따라서 장비에 장애가 발생하더라도 실제 서비스 통신에는 미치는 영향이 비교적 작다.

반면 공격을 발견한 시점에는 해당 요청이 이미 서버에 도달했거나 도달 중일 수 있다. 공격을 차단하려면 관리자가 직접 대응하거나 방화벽, IPS, SOAR 등의 다른 시스템과 연동해야 한다.

### NIPS의 동작 방식

NIPS는 패킷을 직접 제어해야 하므로 일반적으로 네트워크 통신 경로에 인라인으로 배치된다. 목적지로 향하는 트래픽이 NIPS를 통과하면서 검사를 받는 구조다.

```text
패킷 수신
    ↓
패킷 및 세션 분석
    ↓
공격 여부와 정책 확인
    ↓
정상 ───→ 목적지로 전달
공격 ───→ 폐기 또는 연결 종료
                 ↓
             이벤트 기록
```

NIPS가 수행할 수 있는 대응은 제품과 정책에 따라 다르다.

- 공격 패킷 폐기
- TCP 연결 종료
- 특정 세션 제한
- 비정상 트래픽 속도 제한
- 일정 시간 동안 출발지 IP 차단
- 다른 보안 시스템에 차단 정보 전달
- 제품에 따라 악성 파일이나 콘텐츠 전송 차단

IP 주소를 기준으로 차단할 때는 주의해야 한다. NAT, 프록시 또는 공유 IP 환경에서는 하나의 IP 주소를 여러 사용자가 함께 사용할 수 있어 정상 사용자까지 영향을 받을 수 있기 때문이다.

### SQL Injection 공격을 예로 들면

공격자가 SQL Injection 문자열이 포함된 요청을 웹 서버에 전송했다고 가정해 보자.

NIDS는 스위치나 TAP이 생성한 복사 트래픽에서 공격 패턴을 발견해 경고와 로그를 생성한다. 하지만 별도의 차단 시스템이 없다면 원본 요청은 웹 서버로 전달된다.

```text
[NIDS 환경]

공격 요청
   ↓
스위치 또는 TAP
   ├─ 원본 트래픽 ─→ 웹 서버
   └─ 복사 트래픽 ─→ NIDS ─→ 경고 및 로그 생성
```

NIPS는 웹 서버 앞의 통신 경로에서 요청을 검사한다. 공격으로 판단되면 해당 패킷을 폐기하거나 연결을 종료하고 정상적인 요청만 서버로 전달한다.

```text
[NIPS 환경]

공격 요청
   ↓
NIPS가 인라인에서 분석
   ↓
공격으로 판단
   ↓
패킷 폐기 또는 연결 종료
```

## 3. 공격을 탐지하는 방법

IDS와 IPS는 하나의 기준만으로 공격을 판단하지 않는다. 일반적으로 시그니처, 이상 행위, 프로토콜 상태, 위협 인텔리전스 등을 함께 사용한다.

| 탐지 방식 | 판단 기준 | 장점 | 한계 |
| --- | --- | --- | --- |
| 시그니처 기반 | 알려진 공격의 패턴 | 공격 유형을 빠르고 구체적으로 식별 | 새로운 공격이나 변형 공격 탐지가 어려움 |
| 이상 행위 기반 | 정상 상태에서 벗어난 행동 | 알려지지 않은 공격을 찾을 가능성이 있음 | 환경 변화로 인한 오탐 발생 가능 |
| 상태 기반 분석 | 프로토콜의 정상적인 상태와 흐름 | 비정상적인 통신 절차 탐지에 효과적 | 세션 분석에 많은 자원이 필요할 수 있음 |
| 위협 인텔리전스 기반 | 악성 IP, 도메인, 파일 해시 등의 IOC | 이미 확인된 위협을 빠르게 식별 | 정보의 최신성과 신뢰도에 영향을 받음 |

### 시그니처 기반 탐지

이미 알려진 공격의 특징을 탐지 규칙으로 만든 뒤 현재 트래픽과 비교하는 방식이다.

대표적인 탐지 대상은 다음과 같다.

- 알려진 취약점을 이용하는 공격 코드
- SQL Injection이나 XSS에 사용되는 문자열
- 악성코드가 사용하는 통신 패턴
- 특정 익스플로잇의 패킷 구조
- 비정상적인 프로토콜 명령

알려진 공격은 비교적 빠르고 정확하게 분류할 수 있다. 하지만 규칙에 등록되지 않은 새로운 공격이나 기존 패턴을 변형한 공격은 놓칠 수 있으므로 탐지 시그니처를 꾸준히 업데이트해야 한다.

### 이상 행위 기반 탐지

평상시의 네트워크 또는 시스템 활동을 기준으로 만들고, 이 기준에서 크게 벗어난 행동을 찾는 방식이다.

예를 들어 갑작스러운 트래픽 증가, 여러 포트에 대한 반복적인 연결, 평소와 다른 외부 목적지로의 통신 등을 의심할 수 있다.

이상 행위 분석에 사용하는 정보는 제품마다 다르다. 네트워크 흐름을 분석하는 제품도 있고 호스트 로그나 사용자 행동 정보를 함께 활용하는 제품도 있다. 사용자와 계정 단위의 상세한 행동 분석은 NDR, EDR 또는 UEBA와 연계해 수행되기도 한다.

### 상태 기반 프로토콜 분석

TCP, HTTP, DNS 등 각 프로토콜의 정상적인 통신 절차를 기준으로 비정상적인 요청을 탐지하는 방식이다.

단순히 특정 문자열만 찾는 것이 아니라 연결 순서, 명령 형식, 세션 상태 등을 함께 확인하기 때문에 프로토콜을 비정상적으로 사용하는 공격을 찾는 데 유용하다.

### 위협 인텔리전스 기반 탐지

이미 악성으로 확인된 IP 주소, 도메인, URL, 파일 해시 등의 침해지표인 IOC를 네트워크 트래픽이나 수집된 파일·이벤트 정보와 비교하는 방식이다.

IOC는 공격 코드의 구조나 특징을 나타내는 시그니처와 구분된다. 이미 확인된 위협을 빠르게 찾을 수 있지만, 공격자가 IP 주소나 파일을 변경하면 기존 IOC의 효력이 떨어질 수 있다. 따라서 정보의 최신성과 출처의 신뢰도가 중요하다.

## 4. 감시 대상과 배치 방식에 따른 유형

IDS와 IPS는 분석하는 데이터와 보호 대상에 따라 네트워크 기반과 호스트 기반으로 구분할 수 있다.

| 유형 | 감시 대상 | 일반적인 배치 | 특징 |
| --- | --- | --- | --- |
| NIDS | 네트워크 패킷 | 미러링 포트, 네트워크 TAP | 여러 시스템의 통신을 한 번에 감시 |
| HIDS | 호스트 로그, 파일, 프로세스 | 서버 또는 PC 내부 | 개별 시스템의 변화를 상세하게 확인 |
| NIPS | 네트워크 패킷 | 원본 네트워크 통신 경로 | 공격 트래픽을 실시간으로 차단 |
| HIPS | 호스트 내부 행위 | 서버 또는 PC 내부 | 악성 프로세스나 파일 변경 등을 차단 |

### NIDS: 네트워크 기반 침입 탐지 시스템

NIDS(Network-based IDS)는 네트워크를 통과하는 패킷을 수집해 공격 여부를 분석한다.

하나의 지점에서 여러 시스템의 통신을 감시할 수 있어 전체적인 공격 흐름을 파악하는 데 유리하다. 그러나 트래픽이 장비의 처리 용량을 초과하면 일부 패킷을 놓칠 수 있으며, 암호화된 통신은 복호화 없이는 내부 내용을 확인하기 어렵다.

### HIDS: 호스트 기반 침입 탐지 시스템

HIDS(Host-based IDS)는 서버나 PC에 설치되어 해당 시스템의 활동을 감시한다.

운영체제 로그, 로그인 기록, 중요 파일 변경, 프로세스 실행, 계정 및 권한 변경 등을 확인할 수 있다. 시스템 내부에서 발생한 변화를 자세히 파악할 수 있지만 각 장비에 프로그램을 설치하고 관리해야 한다.

### NIPS: 네트워크 기반 침입 방지 시스템

NIPS(Network-based IPS)는 네트워크 경로에서 패킷을 검사하고 공격 트래픽을 차단한다.

인터넷과 내부망 사이, 데이터센터의 중요 서버 구간, 내부 네트워크의 보안 경계 등에 배치할 수 있다. 여러 시스템을 한 번에 보호할 수 있지만 장비의 성능 저하나 장애가 전체 통신에 영향을 줄 수 있다.

### HIPS: 호스트 기반 침입 방지 시스템

HIPS(Host-based IPS)는 개별 서버나 PC에서 악성 행위를 탐지하고 차단한다.

허가되지 않은 프로그램 실행, 중요 파일 변경, 비정상적인 권한 상승 등을 제한할 수 있다. 시스템 내부 행동을 직접 통제할 수 있는 대신 정책이 잘못 설정되면 정상 프로그램의 실행까지 방해할 수 있다.

## 5. 운영 시 주의해야 할 점

IDS와 IPS의 탐지 결과가 항상 정확한 것은 아니다. 운영 과정에서는 오탐, 미탐, 알람 피로, 성능과 같은 문제를 함께 관리해야 한다.

### 오탐과 미탐

오탐(False Positive)은 정상적인 행동을 공격으로 잘못 판단하는 경우다.

IDS에서 오탐이 발생하면 불필요한 경고가 늘어난다. IPS에서 오탐이 발생하면 정상 트래픽이 실제로 차단될 수 있어 서비스 장애로 이어질 가능성이 있다.

미탐(False Negative)은 실제 공격을 정상 행동으로 판단해 탐지하지 못한 경우다. 경고 자체가 발생하지 않기 때문에 공격자가 장기간 활동하더라도 관리자가 알아차리지 못할 수 있다.

탐지 기준을 너무 민감하게 설정하면 오탐이 늘고, 느슨하게 설정하면 미탐이 증가할 수 있다. 서비스 특성과 보호 대상의 중요도를 고려해 탐지 수준을 조정해야 한다.

### 알람 피로

IDS가 발생시키는 경고가 지나치게 많으면 보안 담당자가 모든 이벤트를 확인하기 어려워진다. 그 결과 실제로 중요한 공격이 반복되는 낮은 위험도의 경고에 묻힐 수 있다.

자산의 중요도, 실제 취약점 존재 여부, 공격 성공 가능성 등을 함께 고려해 이벤트의 우선순위를 정해야 한다.

### 성능과 서비스 영향

NIPS는 모든 패킷을 실시간으로 검사하므로 충분한 처리 성능이 필요하다.

네트워크 대역폭뿐 아니라 동시 세션 수, 초당 신규 연결 수, 패킷 크기, 활성화할 탐지 규칙도 함께 고려해야 한다. TLS 복호화나 파일 분석 같은 기능을 사용하면 실제 처리 성능이 장비의 표시 사양보다 낮아질 수 있다.

## 6. 어디에 배치하고 활용하는가?

IDS와 IPS는 보호하려는 자산과 예상되는 공격 경로에 따라 적절한 위치에 배치해야 한다.

### 외부 네트워크 경계

인터넷과 내부 네트워크 사이에서 외부 스캔, 취약점 공격, 악성코드 통신 등을 감시하거나 차단할 수 있다.

다만 외부에서 발생하는 모든 공격 시도를 같은 수준으로 처리하면 경고가 지나치게 많아질 수 있다. 공격 대상이 실제로 내부에 존재하는지, 관련 취약점이 있는지를 함께 확인해 우선순위를 결정하는 것이 효과적이다.

### 웹 서버와 중요 서버 구간

웹 서버, 데이터베이스 서버, 인증 서버처럼 중요한 시스템 앞에 NIPS를 배치하면 공격 트래픽이 서버에 도달하기 전에 차단할 수 있다.

공개 웹 서비스에는 WAF와 IPS를 함께 사용할 수 있다. WAF는 HTTP 요청과 웹 애플리케이션 공격을 집중적으로 분석하고, IPS는 더 넓은 범위의 네트워크 및 프로토콜 공격을 탐지한다.

### 내부 네트워크

외부 공격뿐 아니라 내부 확산도 감시해야 한다.

악성코드에 감염된 PC가 다른 내부 서버를 스캔하거나 공격할 경우 인터넷 경계에만 설치된 장비로는 이를 확인하기 어렵다. 중요 업무망과 서버망 사이에 IDS·IPS를 배치하면 내부 이동과 공격 확산을 탐지하는 데 도움이 된다.

### 침해 사고 분석

IDS와 IPS 로그에는 공격 시간, 출발지와 목적지, 포트, 프로토콜, 탐지 규칙, 대응 결과 등이 기록된다.

방화벽, 서버, 인증 시스템, EDR 등의 로그와 함께 분석하면 공격자가 어떤 경로로 접근했고 어떤 시스템을 공격했는지 파악할 수 있다.

## 7. 다른 보안 솔루션과의 차이

IDS와 IPS는 다른 보안 시스템을 대체하기보다 서로 부족한 부분을 보완한다.

| 보안 시스템 | 주요 역할 |
| --- | --- |
| 전통적인 방화벽 | IP, 포트, 프로토콜 등을 기준으로 접근 통제 |
| NGFW | 애플리케이션 분석, 사용자 식별, IPS 등을 통합 제공 |
| IDS | 네트워크 또는 호스트에서 공격 징후 탐지 |
| IPS | 공격 트래픽이나 호스트 행위를 직접 차단 |
| WAF | SQL Injection, XSS 등 웹 애플리케이션 공격 방어 |
| EDR | PC와 서버의 프로세스, 파일, 행위 탐지 및 대응 |
| NDR | 네트워크 흐름과 이상 행위를 분석해 위협 탐지 |
| SIEM | 여러 시스템의 로그를 수집하고 연관 분석 |
| SOAR | 반복적인 보안 분석과 대응 절차 자동화 |

전통적인 방화벽이 허용한 443번 HTTPS 연결에서도 웹 공격이 발생할 수 있다. 해당 공격을 확인하려면 TLS 복호화가 적용된 IPS나 WAF, 웹 서버 로그처럼 암호화된 내용이나 복호화 이후의 요청을 분석할 수 있는 지점이 필요하다.

IDS가 의심스러운 통신을 탐지하면 SIEM이 다른 보안 로그와 연관 분석하고, SOAR가 검증된 절차에 따라 방화벽이나 EDR에 대응을 요청하는 구조도 만들 수 있다.

실제 보안 환경에서는 하나의 장비가 모든 위협을 처리하기보다 여러 보안 시스템이 정보를 공유하며 함께 대응한다.

## 8. 효과적인 운영 방법과 한계

### 탐지 모드부터 시작한다

새로운 규칙을 처음부터 차단 모드로 적용하면 정상 서비스가 중단될 수 있다.

먼저 탐지 모드에서 어떤 이벤트가 발생하는지 확인하고, 정상 트래픽과 오탐을 구분한 뒤 차단 모드로 전환하는 것이 안전하다.

```text
탐지 정책 적용
      ↓
이벤트와 오탐 분석
      ↓
정상 트래픽 예외 처리
      ↓
일부 구간에서 차단 적용
      ↓
전체 적용 및 지속적인 관찰
```

### 정책과 시그니처를 관리한다

새로운 취약점과 공격 기법이 계속 등장하므로 탐지 시그니처와 위협 인텔리전스를 최신 상태로 유지해야 한다.

모든 규칙을 무조건 활성화하기보다 실제 운영체제, 서비스, 애플리케이션과 관련된 규칙을 우선 적용하는 것이 효율적이다. 사용하지 않는 서비스의 규칙까지 모두 활성화하면 성능 부담과 불필요한 경고가 증가할 수 있다.

### 자산 정보와 함께 판단한다

같은 공격이라도 대상에 따라 위험도가 달라진다.

실제로 취약한 서버를 대상으로 한 공격과 해당 서비스를 사용하지 않는 서버를 대상으로 한 공격은 대응 우선순위가 다르다. 자산의 중요도와 취약점 정보를 탐지 이벤트에 함께 반영하면 경고를 더 정확하게 분류할 수 있다.

### 암호화된 트래픽을 고려한다

HTTPS와 같은 TLS 암호화 통신은 복호화하지 않으면 IDS나 IPS가 내부의 요청 내용을 확인하기 어렵다.

암호화된 통신을 분석하려면 다음과 같은 방법을 사용할 수 있다.

- 보안 장비에서 TLS 복호화 수행
- 리버스 프록시나 로드밸런서의 복호화 지점에서 검사
- 웹 서버 또는 애플리케이션 로그 활용
- EDR이나 HIDS를 이용해 호스트 내부 행위 확인

TLS 복호화를 사용하면 분석 범위가 넓어지지만 장비의 CPU와 메모리 사용량이 증가할 수 있다. 인증서 관리, 개인정보 보호, 법적 요구사항도 함께 고려해야 한다.

금융, 의료 또는 개인정보가 포함된 트래픽은 무조건 복호화하기보다 조직의 정책과 관련 규정을 기준으로 예외 범위를 정해야 한다.

### 장애에 대비한다

NIPS는 통신 경로에 있으므로 장애 상황에서 트래픽을 어떻게 처리할지 결정해야 한다.

- **Fail-open:** 장애가 발생하면 트래픽을 통과시킨다.
- **Fail-closed:** 장애가 발생하면 트래픽을 차단한다.

Fail-open은 서비스 연속성을 유지할 수 있지만 장애 중에는 보안 검사가 이루어지지 않는다. Fail-closed는 검사되지 않은 통신을 막을 수 있지만 정상 서비스까지 중단될 수 있다.

중요한 구간에서는 장비 이중화, 우회 경로, 장애 전환 테스트도 함께 준비해야 한다.

### IDS와 IPS의 한계를 이해한다

IDS와 IPS가 모든 공격을 발견하거나 차단할 수 있는 것은 아니다.

암호화된 트래픽, 시그니처가 없는 새로운 공격, 정상 계정을 이용한 접근, 정상 요청과 유사하게 위장한 공격은 네트워크 분석만으로 판단하기 어려울 수 있다. 공격자가 트래픽을 여러 패킷으로 나누거나 매우 느린 속도로 행동하면 단순한 탐지 기준을 우회할 가능성도 있다.

따라서 IDS와 IPS만 의존하기보다 다음과 같은 보안 대책을 함께 운영해야 한다.

- 운영체제와 프로그램의 보안 업데이트
- 방화벽과 WAF를 이용한 접근 통제
- EDR을 이용한 호스트 행위 분석
- 안전한 계정 및 권한 관리
- SIEM을 이용한 통합 로그 분석
- 중요 데이터에 대한 접근 통제
- 정기적인 취약점 점검
- 침해 사고 대응 절차 수립과 훈련

## 자주 묻는 질문

### IDS와 IPS를 모두 설치해야 하나요?

반드시 별도의 장비 두 대를 설치해야 하는 것은 아니다. 하나의 장비나 NGFW가 IDS와 IPS 기능을 모두 제공할 수 있다.

중요한 것은 제품 수가 아니라 필요한 구간에서 탐지와 차단 기능이 적절하게 동작하는지다. 네트워크 전체를 폭넓게 관찰할 때는 IDS 방식이 유리하고, 중요 서버 앞에서 즉시 차단해야 할 때는 IPS 방식이 적합하다.

### IPS는 방화벽을 대체할 수 있나요?

완전히 대체할 수 없다.

방화벽은 네트워크 접근을 허용하거나 차단하는 기본 통제 역할을 담당하고, IPS는 허용된 통신 내부에 포함된 공격 패턴이나 비정상적인 행위를 추가로 검사한다. 두 시스템은 역할이 다르므로 함께 사용하는 것이 일반적이다.

### IDS가 공격을 직접 차단할 수도 있나요?

제품 구성과 연동 방식에 따라 가능하다.

IDS가 직접 인라인 차단을 수행하지 않더라도 방화벽이나 SOAR에 정보를 전달해 공격자의 접속을 제한할 수 있다. 다만 IDS가 직접 패킷을 폐기한 것인지, 다른 시스템에 차단을 요청한 것인지는 구분할 필요가 있다.

### HTTPS 공격도 IPS가 탐지할 수 있나요?

TLS 복호화가 적용되거나 복호화 이후의 요청을 검사할 수 있다면 탐지할 수 있다.

복호화되지 않은 HTTPS 통신에서도 출발지·목적지 IP 주소, 포트, 패킷 크기, 연결 시간과 같은 메타데이터는 확인할 수 있다. 하지만 암호화된 HTTP 요청의 URL, 헤더, 본문 등 상세 내용은 확인하기 어렵다.

## 마무리

IDS와 IPS의 가장 큰 차이는 공격을 발견한 뒤의 대응 방식이다. IDS는 의심스러운 활동을 탐지하고 기록하며, IPS는 네트워크 통신이나 호스트의 행위에 직접 개입해 공격을 차단한다.

실제 환경에서는 두 기능이 하나의 장비나 차세대 방화벽에 통합되기도 한다. 효과적으로 운영하려면 탐지 규칙을 업데이트하는 것뿐 아니라 오탐 분석, 정책 조정, 성능 산정, 암호화 트래픽 처리와 장애 대응까지 함께 고려해야 한다.
