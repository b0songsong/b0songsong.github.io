블로그 화면 열기 ↗자세한 사용 안내

압축을 먼저 완전히 푼 뒤 이 파일을 연다. 현재는 공개 배포 전이며, 실제 github.io 주소는 자신의 GitHub 저장소에서 Pages를 활성화한 뒤 생성된다.

01 / FIRST PUBLISH

웹사이트에서 첫 배포하기

프로그램 설치 없이 완성된 페이지를 올리는 방법이다.

1

저장소 생성

GitHub에서 새 저장소를 만든다. 이름은 아이디.github.io, 공개 범위는 Public, Add README는 켜기로 설정한다.

2

docs 폴더 업로드

저장소의 Add file → Upload files에서 이 압축 파일의 docs 폴더를 통째로 올리고 Commit changes를 누른다. 저장소에 docs/index.html이 있어야 한다.

3

Pages 켜기

Settings → Pages에서 아래 값을 선택하고 Save를 누른다.

설정선택
SourceDeploy from a branch
Branchmain
Folder/docs
4

공개 주소 확인

Actions에서 배포 성공을 확인한 뒤 Settings → Pages의 Visit site를 누른다. 게시에 최대 10분 정도 걸릴 수 있다.

상위 bosongsong-blog 폴더까지 중첩해서 업로드하지 않는다. 자세한 설정은 GitHub 공식 문서에서 확인할 수 있다.

02 / MAKE IT YOURS

나의 이름과 관심사를 담기

바꿀 내용수정 위치
블로그 이름, 작성자, 홈 소개, 관심 분야, GitHub 주소data/site.json
소개 페이지의 자기소개 문단data/site.json의 about 배열
색상, 글꼴, 화면 간격assets/site.css
학습 기록과 글 내용content/posts/*.md

글에는 예시 노트 표시가 있다. 실제 활동 실적으로 받아들이지 말고, 자신의 학습 기록으로 교체하거나 내용을 검토해 발전시키면 된다.

로컬에서 수정한 내용을 페이지에 반영하려면 Node.js 20 이상을 설치하고 프로젝트 폴더에서 다음 명령을 실행한다. 자동 배포와 같은 환경은 Node.js 24이다.

node scripts/build.mjs

다시 생성된 docs 폴더를 업로드하면 변경 사항이 공개된다. 글을 자주 쓴다면 아래 자동 배포를 설정하면 된다.

03 / WRITE & PUBLISH

Markdown으로 쓰고 자동 배포하기

  1. 프로젝트의 전체 내용을 저장소 최상위에 올린다. content, data, scripts, vendor 등이 첫 화면에 있어야 한다.
  2. .github/workflows/pages.yml도 올라갔는지 확인한다. 빠졌다면 GitHub의 Create new file에서 같은 경로로 만들고 제공 파일의 내용을 붙여넣는다.
  3. Settings → Pages의 Source를 GitHub Actions로 변경한다.
  4. Actions에서 Publish blog to GitHub Pages → Run workflow를 실행한다. Pages 설정 전에 첫 실행이 실패했어도 설정 후 다시 실행하면 된다.
  5. 이후 content/posts의 Markdown 파일을 수정하고 커밋하면 사이트가 자동으로 갱신된다.

새 글은 content/post-template.txt를 content/posts/my-first-note.md처럼 복사해서 작성한다. 자신의 글에는 example: false를 사용한다.

파일 업로드 배포와 자동 배포 중 현재 사용할 방식을 하나 선택한다. 자동 배포의 구조는 GitHub 공식 워크플로 안내를 따른다.
